# בקיבוץ — האתר

האתר החי: **https://bakibutz.netlify.app**

כל האתר הוא קובץ אחד: `public/index.html`. אין שרת, אין בסיס נתונים, אין שלב בנייה.
התמונות והפונטים מוטמעים בתוך הקובץ עצמו.

**כל `git push` לענף `main` מפרסם את האתר לאוויר אוטומטית** (תוך פחות מדקה).

---

## התקנה חד-פעמית במחשב חדש

צריך שני דברים לפני שמתחילים: **מנוי Claude פעיל** (Pro או Max — לכל אחד חשבון משלו),
ו**הרשאת כתיבה לריפו** הזה ב-GitHub (בעל הריפו מזמין, וצריך ללחוץ על ההזמנה במייל).
הריפו עצמו ציבורי — נטליפיי חוסם בנייה מריפו פרטי כשהקומיטר אינו חבר צוות בתשלום.

אחר כך פותחים את Claude (בדסקטופ: טאב **Code**; בטרמינל: `claude`) על תיקייה ריקה
כלשהי — למשל `dev` בתיקיית הבית — ומדביקים את הפרומפט הזה כהודעה הראשונה:

```
זה מחשב חדש ושום דבר עוד לא מותקן. אני עובד/ת על אתר שנמצא בריפו בגיטהאב,
ואני לא מתכנת/ת. תעשה לי את ההתקנה מא' עד ת' ותסביר בעברית מה אתה עושה בכל שלב.
תשאל אותי רק שאלות שאני יכול/ה לענות עליהן.

1. תבדוק מה מותקן אצלי: git ו-gh (GitHub CLI). מה שחסר — תתקין, לפי מערכת ההפעלה שלי.
2. תחבר אותי לגיטהאב עם gh auth login דרך הדפדפן, ותשאל אותי לשם המשתמש שלי.
3. תשאל אותי מה הכתובת של הריפו, ותשכפל אותו לתוך התיקייה הזאת.
4. תחליף את תיקיית העבודה שלך לתיקיית הפרויקט שנוצרה, כדי שההנחיות שבקובץ
   CLAUDE.md שבתוכה ייטענו.
5. תקרא את CLAUDE.md ואת README.md ותסביר לי בקצרה: מה זה האתר, איך שינוי מגיע
   לאוויר, ומה הכלל לגבי עבודה במקביל עם אנשים אחרים.
6. לסיום תריץ git pull ותאמת שהכל תקין.

חשוב: אל תשנה שום דבר באתר עצמו בשלב הזה — זו רק התקנה.
```

בדרך יופיעו בקשות אישור להרצת פקודות — צריך לאשר. בשלב `gh auth login` ייפתח דפדפן
להתחברות לגיטהאב; זה חד-פעמי.

## איך עובדים על האתר

פותחים את Claude על תיקיית הפרויקט (בדסקטופ: טאב Code; בטרמינל: `claude` מתוך
התיקייה), ומבקשים בעברית מה לשנות. התבנית לכל פעם:

```
תמשוך קודם את הגרסה העדכנית של האתר, ואז: <מה שאני רוצה לשנות>.
כשנסיים, תפרסם עם /deploy.
```

לדוגמה: "תמשוך קודם את הגרסה העדכנית של האתר, ואז תחליף את התאריך של הסדנה הבאה
ל-12.3 ותוסיף שנותרו 4 מקומות. כשנסיים, תפרסם עם /deploy."

**`/deploy`** מציג מה עומד לעלות לאוויר, מבקש אישור, דוחף ל-GitHub ומאמת שהאתר החי
עלה. אין צורך לזכור פקודות git.

## שני כללים חשובים

1. **לפני שמתחילים לערוך — תמיד למשוך את הגרסה העדכנית:**
   ```bash
   git pull --rebase
   ```
   (או פשוט לבקש מקלוד "תמשוך את הגרסה העדכנית").
2. **לא לעבוד בו-זמנית על האתר משני מחשבים.** כל האתר הוא קובץ ענק אחד, ואם שניים
   יערכו אותו במקביל — מיזוג השינויים יהיה כמעט בלתי אפשרי, ואחד מהשינויים ילך לאיבוד.
   פשוט להודיע אחד לשני "אני נכנס/ת לערוך" לפני שמתחילים.
